## 2. 本轮重点机制：实测证据

### 2.1 快照经 CAS 分发（不是内嵌）

```
cas: blob d9d0fa96…a47 fetched from 12D3KooW…iDEp (4004352 bytes)
project 41dfe9fb…: snapshot d9d0fa96…a47 ready locally (4004352 bytes)
```

- master 侧：`dispatched to peer … (snapshot 3584 bytes, …)` —— 任务消息里只有 hash；
- executor 侧：先查本地 CAS（前几次任务的 3584 字节快照命中，零网络），
  ~4MB 的工作区则触发一次真实拉取。

**这证明「只发 hash + 按需拉取」在真机上成立**，也顺带验证了 `blob_exchange` 超时调整的必要性
（默认 10s 对 4MB 都不够稳，现在是 900s）。

### 2.2 资源策略在启动时可见（不靠猜）

```
Project sandbox policy: enabled=true, vm_mode=Reuse, pool=1, base_image=builtin
qlean worker: mode=Reuse, pool_target=0 (pooling disabled), reuse=true
```

`pool_target=0` 在 reuse 模式下是**正确行为**（复用本来就只留一台，预热无意义），
日志把这件事说清楚了，避免"我配了池怎么没生效"的疑问。

### 2.3 热/冷路径耗时（本次实测）

| 路径 | 耗时 | 构成 |
|---|---|---|
| 冷路径（首次任务） | ~48s | 镜像准备 31s + VM 启动 15.1s + 执行 36ms |
| 冷路径 + 装工具链 | **17.9s**（VM 已启动时） | 换源后的 `apt install gcc` + 编译 + 运行 |
| 热路径（VM 复用 + gcc 已装） | **31-62ms** | 上传 24ms + 编译 37ms + 运行 31ms |
| eo-agent 端到端（热） | **57ms** | 提交 → 结果 |

对照历史（`15-性能重构`）：冷 51.5s / 热 68ms —— 冷路径的「装工具链」部分从不可预期
（曾经 300s 超时）变成**受镜像带宽约束的确定性开销（18s）**。

## 3. 隔离：机制已实现，但我的探针曾经测错

**已实现**：
- `VmMode::{Reuse, Fresh}`（`fresh` = 每任务新 machine = 独立 qcow2 overlay，任务结束即丢弃）；
- VM 池（fresh 模式下空闲时预启动补池，隐藏 14s 启动等待）；
- 自定义基础镜像（模板）配置 + 前置换校验。

**探针缺陷（本次实测暴露）**：stage G 原本把标记文件放在 **work_dir 里**，而
`execute_on_vm` 在**两种模式**下都会先 `rm -rf <work_dir>`，所以 reuse 模式也报 `MARKER-GONE`，
看起来"隔离成立"，实际上什么都没测到。

**已修**：探针改为 `/root/eo-isolation-marker`（工作目录之外），
并新增 stage G3 用独立端口起 3 个 `--project-vm-mode fresh --project-vm-pool-size 0` 的节点做对照。

| 观察 | 结论 |
|---|---|
| `MARKER-SURVIVED-reuse-is-not-isolated` | reuse：任务间共享磁盘（预期） |
| `MARKER-GONE-isolated` | fresh：新 machine，标记被丢弃 |

**诚实说明**：修正后的探针**尚未在你的机器上跑过**，所以"隔离成立"目前只有单测支撑
（`VmMode`/`PoolPlan`/配置解析），没有真机证据。

## 7. 已知的、不该被遗忘的事实

- **`fresh` 模式的代价**：池化只隐藏"启动 14s"，不隐藏"装工具链 18s"；
  两者都解决需要模板镜像（配置已就绪，镜像未造）；
- **本机（macOS）看不到 Linux 门控代码**：`fmt`/`clippy`/`test` 全绿也可能编译不过，
  必须看 CI（ubuntu job）——这一点已经写进 `09-Phase1-bug归档.md`，并连续踩了 5 次；
- **`apt-get update` 会在所有源都失败时仍返回 0**，任何"装成功了吗"的判断都必须基于
  真实 HTTP/文件检查，而不是退出码。
