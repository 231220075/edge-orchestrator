启动 3 节点（配置 configs/cluster-node-{1,2,3}.yaml，固定端口 39001-3、固定 identity seed、bootstrap peers 互拨）：
```
for i in 1 2 3; do RUST_LOG=info ./target/debug/node --config configs/cluster-node-$i.yaml --store-dir /tmp/eo-it/n$i --ipc-socket /tmp/eo-it/n$i.sock > /tmp/eo-it/n$i.log 2>&1 & done
```

kill leader：kill -9 后 RAFT_LEADER raft_id=3（重选主成功）。
任务：./target/debug/examples/submit_task /tmp/eo-it/n1.sock 返回 code_hash+task_id；日志出现 SCHED assign task -> raft 3、EXEC raft 3 finished task exit=0、Task completed。

## 关键设计与实现

- raft 消息走 /edge-orch/raft/1.0.0 的 request-response，请求体只含 protobuf 字节（from/to 在 raft Message 头部）。
- RaftIdRegistry：raft_id -> PeerId 映射，靠 descriptor 交换建立；descriptor 交换必须在收到请求时 send_response（v0.1 只打日志不回包，是致命 bug）。
- raft-rs Ready 协议必须 send persisted_messages()（非 leader 的投票请求在 persisted_messages 里，普通 messages() 为空），并持久化 hard state / entries 后再 advance。
- 静态 3 节点：CasRaftStorage.new_empty(voters=[1,2,3]) 写入 ConfState；pre-vote + check_quorum 开启。
- 节点自注册：RegisterNode 周期性重提直到被 leader 提交（首次 propose 可能在选举完成前被 drop）。
- 调度/执行：coordinator_loop 每 500ms 扫描任务队列并 propose AssignTask；executor_loop 执行分给自己的任务并 propose CompleteTask；at-least-once 语义（超时重路由，可能重复执行）。
- 网状维护：启动时拨 bootstrap peers；每 2s 重拨 bootstrap + 已知 peer 地址；ConnectionClosed 后重拨，修复 mDNS 竞态/nat 波动。

## 开发中遇到的难题（全部有解并落地）

1. descriptor 交换 "response channel dropped"：v0.1 从不 send_response。解法：在 swarm 内调用 behaviour.send_response(channel, response)。
2. raft 投票请求不发出：Ready.messages() 对非 leader 恒为空，真正的消息在 persisted_messages()；必须先持久化再发。这是 raft-rs 经典陷阱。
3. mDNS 只处理第一个 peer：原 handle 循环里 return；改为返回 Vec<Event> 全部处理。
4. 节点映射丢失/网络裂开：mDNS 竞态 + 连接关闭后不重连。解法：bootstrap peers 周期重拨 + peer 地址簿 + ConnectionClosed 重拨。
5. 首次 RegisterNode 被 drop：propose 早于选举完成。解法：注册循环每 2s 重提直到入 state。

## 诚实边界

- 成员变更（AddNode/RemoveNode/joint consensus）为 stub，静态 3 节点。
- blob 分发未接 P2P：任务用 code_inline 内联字节码（ScheduledTask 新增字段）；生产应走 CAS 同步，已在 06 方案文档标注。
- 失败检测是超时重路由（粗粒度），非 member 心跳。
- at-least-once 语义：故障节点上的任务可能重复执行。
