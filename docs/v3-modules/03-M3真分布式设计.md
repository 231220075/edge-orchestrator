# M3 真分布式设计（定稿）

> 目标：3 节点 Raft 走 libp2p 联通；kill leader 重选主；任务从死者节点重路由到存活节点。
> 验收：单机多进程自动集成测试（可复现）+ 跨机演示脚本（录屏用）。

## 决策（已与用户确认）

1. raft id = 静态 1/2/3，配置文件显式指定；成员变更 stub（AddNode/RemoveNode 不做）。
2. M3 证据 = 单机多进程可自动回归的集成测试 + 跨机手动演示脚本。
3. 任务重路由 = at-least-once 语义（可能重复执行，文档诚实标注）。

## 子任务拆解

- M3.1 P2P 协议扩展：新增 raft 消息与 blob 分发两个 request-response 协议。
- M3.2 重写 raft transport：PeerRegistry 实现 node_id(raft id) 到 PeerId 映射，真发送。
- M3.3 node bootstrap 接线：config 读 raft_id 与 peer 列表；descriptor 注册进 raft。
- M3.4 集成测试框架：单机 3 进程；kill leader；断言重选主与任务重路由。
- M3.5 任务状态机：ClusterState 增加任务 pending 队列与 executor 失败重入队。

## 关键设计

### raft id -> PeerId 映射

- descriptor 交换建立映射：收到 descriptor 时，依据 descriptor.node_id 关联 PeerId。
- raft 消息 envelope 带 `from_raft_id` / `to_raft_id`，swarm 侧查表把 to_raft_id 换成 PeerId 投递。

### 任务状态语义（at-least-once）

提交任务 -> Raft 提交 SubmitTask -> state machine apply 写入 task_queue 并保留 task_id ->
调度器取队首并指定 executor -> executor 执行 -> 完成后提交 CompleteTask。
若 executor 心跳超时（kill），任务仍在 task_queue（不删除直到 CompleteTask），新 leader
重读 task_queue 并重新路由。代价：任务可能被执行两次（诚实边界）。

### 测试框架

- scripts/run_3node_integration.sh：起 3 个 node 进程（不同端口/store/ipc），注入任务，
  记录日志；kill 一个，sleep 观察重选主。
- Rust 侧集成测试 tests/cluster_raft.rs（可选，依赖多进程启动，优先用 shell 脚本做可复现）。
