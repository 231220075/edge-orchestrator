## 背景与本模块目标

v0.1 的 8 crate 中，p2p 与 raft 必须同生命周期、互相转发消息，拆开后只能靠 mpsc stub 糊住；orchestration 与 ipc 两个 crate 甚至没有被 node 主进程接线，属于死代码。M1 把它们收敛为 node 单二进制的内部模块，边界落在 trait/模块层。

## 最终 crate 列表

- core    —— 类型/错误/trait（保留）
- storage —— CAS Git 模型（保留，最强资产）
- sandbox —— Wasmtime + 诚实 container stub（M2 补强）
- p2p     —— libp2p 网络层（M3 补 raft 消息/分发协议）
- node    —— 唯一二进制，吸收 raft/orchestration/ipc 三个模块

## 关键技术问题与解法

1. **use 路径重写**：eo_raft:: -> crate::raft::；内部 crate::network -> crate::raft::network；orchestration 内部 crate::topology -> crate::orchestration::topology。用 sed 批处理并逐文件复查。
2. **模块级告警**：raft/orchestration/ipc 原为 library crate 的 pub 项，变成 binary 内部模块后触发大量 dead_code（M1 阶段确实未接线）。处理方式：在 mod.rs 顶部加 #![allow(dead_code)] / #![allow(unused_imports)]，并写注释说明 M3 接线后逐个移除，不删除已写好的实现与单测。
3. **开发环境陷阱（值得记录）**：bash history expansion 会把 '![...]' 误解析，导致写 #![allow(...)] 时命令挂机。解法：用 python chr(35)+chr(33) 拼接，避免在命令文本中出现字面量 #! 或 ![。
