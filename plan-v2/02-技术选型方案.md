## 一、三个灵魂问题的直接回答

| 问题 | 结论 | 理由 |
|---|---|---|
| 需不需要自组网？ | **不需要「自研」自组网** | libp2p 就是现成自组网协议栈，只需正确配置 mDNS + 手动 peer 兜底 |
| 需不需要分布式？ | **需要，但必须是「有意义的分布式」** | 否则又回到「Raft 但单节点」的空架子 |
| 需不需要微服务？ | **绝对不要** | v0.1 最大的伪装税，8 crate = 过度工程 |

## 二、选型总表（面试必背的候选 + 淘汰理由）

| 决策点 | 推荐 | 淘汰候选 | 淘汰理由 |
|---|---|---|---|
| 组网 | libp2p（mDNS + Noise + Yamux，手动 peer 兜底） | 自研组网协议 | 重复造轮子、无安全审计 |
| 一致性 | Raft（tikv/raft-rs RawNode 手动驱动） | Paxos / 纯 gossip | Paxos 难工程化；已有 raft-rs 资产 |
| 沙箱 | Wasmtime 为主，Linux namespace+cgroup 为辅 | 纯 Docker / Firecracker | Docker 引擎重非库；Firecracker 过重 |
| 存储 | Git 模型 CAS（本人最强项） | 直接上对象存储 | 复用资产，内容寻址天然去重 |
| 服务化 | 单二进制 + 本地 UDS IPC | gRPC 微服务拆分 | 局域网演示不需网络级服务拆分 |
| Agent 层 | 薄 prompt→JSON，暂不接重框架 | LangGraph/多智能体 | 用户明确不想堆 agent 栈，且是 v0.1 烫手山芋 |

> 叙事主线：「控制面 Raft 保证元数据 CP，数据面 CAS 保证去重与 AP，libp2p 做设备无关的传输。」

## 三、架构分层（保留的最小闭环）

```
┌─────────────── 前端：自然语言 → 结构化任务（极简 prompt→JSON）───────────────┐
│  iPhone / CLI / Web  →  { kind: "execute", code, target, limits }          │
└──────────────────────────────┬──────────────────────────────────────────┘
                               │ UDS / JSON-RPC 2.0
┌──────────────────────────────▼──────────────────────────────────────────┐
│  Node 单二进制（Rust）                                                    │
│  ├─ 控制面：Raft（RawNode）—— 维护节点表 + 任务路由表                     │
│  ├─ 数据面：CAS 存储（Git 模型，复用 storage crate）                       │
│  ├─ 传输：libp2p（Raft 消息 + blob 分发 同走 libp2p）                      │
│  └─ 执行：Sandbox trait（Wasmtime / Linux namespace+cgroup）              │
└─────────────────────────────────────────────────────────────────────────┘
```

## 四、模块合并方案（8 → 4）

| 原 crate | 去留 | 说明 |
|---|---|---|
| core | ✅ 保留 | 类型/错误/接口定义 |
| storage | ✅ 保留 | 最强资产 |
| sandbox | ✅ 保留 | 补强限额语义 |
| p2p + raft + orchestration + ipc + node | 合并为 `node` | 传输联通逻辑内聚到一处，ipc/orchestration 下沉为 node 内部模块 |

合并动机：p2p 与 raft 本就必须同生命周期、互传消息，拆开反而制造了「mpsc stub 没联通」的断层。合成一个进程内聚的边界，比假装是微服务更诚实、更好讲。

## 五、沙箱隔离的「可证伪」要点（本轮补强）

- Wasm 隔离面：线性内存（无裸指针逃逸）、import/export 白名单、`StoreLimits` 限制内存 + `epoch-based interruption` 掐死死循环。
- Container 隔离面：namespace（pid/mnt/net/uts/ipc/user）+ cgroup v2（memory.max / cpu.max / pids.max），并讲清「namespace 隔离了什么、cgroup 限制了什么、二者边界在哪」。
- 演进方案（诚实边界）：Wasm 资源耗尽 = fuel + StoreLimits；Container 限额 = cgroup v2 统一层级，不做 v1 legacy。
