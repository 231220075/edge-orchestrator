## 二、自愈演示（本轮「分布式意义」的核心证据）

这个 demo 是面试杀手锏，必须做成可录屏、可复述：

```
1. 启动 3 个节点（Mac + Linux VM + 任意第三节点）
2. 提交一个任务 → 观察到 Raft 日志在 3 节点间复制
3. kill -9 掉当前 leader
4. 观察剩余节点在 election_timeout 内重新选举出新 leader
5. 观察原本路由到死者节点的任务，被重新路由到存活节点并执行成功
6. 输出：「故障 → 重选主 → 任务重路由」三段式证据链
```

### 面试时如何讲这个 demo（三层）

- **原理**：election timeout 触发 Pre-Vote → 成为 candidate → 拿到多数派投票 → 成为 leader → 提交新 term 的 no-op 日志 → 心跳恢复。
- **选型**：为什么用 raft-rs 的 RawNode 手动驱动而不是高层实现？——为了精确控制 tick/step/ready/advance 流程，且在面试里讲得出每一拍的字节级语义。
- **边界**：CheckQuorum 开没开、joint consensus 做没做、成员变更到哪一步——诚实说 stub。

## 三、Agent 层的极简落地（替代 LangGraph）

- 输入一句话 → 模板化 prompt → 要求 LLM 只返回严格 JSON：`{ kind, code, target, limits }`
- 不再用 LangGraph 的 node/edge 图；控制流回到开发者手里（对应 AGENT_PLAN.md 里「workflow vs agent」的结论：确定性拓扑 + 局部 LLM 动态）。
- 好处：token 可控、可控性强、面试可讲「为什么不引入多智能体」（直接引用 AGENT_PLAN.md 的 Token 爆炸论）。
