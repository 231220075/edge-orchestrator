# Edge-Orchestrator 二次重构 · 核心诊断

> 结论先行：v0.1 是一个「单进程堆 8 crate、Raft 单节点装样子、P2P 与 Raft 未握手、Agent 栈烫手」的漂亮空壳。
> 本次重构的第一目标不是「更完整」，而是「每个组件都能在面试里讲出『原理 + 选型对比 + 诚实边界』三层」。
> 宁可 3 个亮点讲透，不要 8 个名词都只讲 10%。

## 一、资产盘点（逐行核对源码后）

| 模块 | 真实状态 | 行数 | 能否复用 |
|---|---|---|---|
| storage（CAS + Git 模型 + zlib + packfile + 读校验） | 最扎实，真实现 | 980 | ✅ 最大资产，直接复用 |
| sandbox（Wasmtime + Container trait + 动态分发） | 代码在，限额/隔离是半成品 | 360 | ⚠️ 需补强限额语义 |
| raft（RawNode 手动驱动） | 传输是 mpsc stub，未联通 P2P，单节点才跑 | 1107 | ❌ 纸面 Raft |
| storage/transport.rs | 源码明确写 stub，P2P 对象分发没接 | — | ❌ |
| p2p | mDNS/Noise/Yamux 在，无 gossipsub，未与 Raft 联通 | 613 | ⚠️ |
| Python eo-agent（LangGraph ReAct） | 991 行，重框架 | 991 | ⚠️ 本轮要砍/移的主体 |

## 二、根本病灶

1. **过度工程伪装成微服务**：8 个 crate 全在一个进程里，不是微服务，是分类癖。
2. **分布式没有「分布式意义」**：Raft 只对单节点生效，断网自愈场景（plan.md 自己都写了「面试极其震撼」）从未兑现。
3. **Agent 栈喧宾夺主**：LangGraph 重框架只贡献了 vibecoding 的炫技，没贡献「分布式/沙箱」这两个真亮点，还成了 Shopee 二面被打穿的直接引信。

## 三、三条整改铁律

1. **砍掉伪装税**：能并的 crate 并，能降级的组件降级，保留最小可演示闭环。
2. **每个亮点三层表达**：原理 → 选型对比（列出被淘汰候选及理由）→ 诚实边界（哪是 stub、演进方案是什么）。
3. **分布式要有可证伪的证据**：必须有「杀掉节点 → 观察重新选主 → 任务重路由」的可演示 demo，否则 Raft 就没有存在理由。
